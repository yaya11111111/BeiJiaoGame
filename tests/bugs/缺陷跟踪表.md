## BUG-001 构建产物里 `[...set]` 变成 `[].concat(set)`

- **发现时间 / 发现人**：≤2026-09-26 / D
- **复现步骤**：对 `Set` 用展开运算符（如 `[...someSet]`），在微信开发者工具里跑构建产物
- **预期结果**：拿到 Set 里的元素
- **实际结果**：`TypeError: s is not a function`
- **根因**：Cocos 构建管线用 Babel loose 模式编译，`[...set]` → `[].concat(set)`，而 `concat` 不展开 Set，于是拿到 `[set 自己]`。压缩后变量名全是 `s`，栈里看不出是 Set。
- **严重级别**：严重
- **关联需求**：FR-07
- **状态 / 修复人 / 关闭时间**：已关闭 / D / ≤09-26（复测人：D）
- **修法**：改用 `common/Collections.ts` 的 `setToArray()`；并加**源码守护** —— `collections.test.ts` 会扫每个 `[...x]`，不在白名单就失败。
- **备注**：这类 bug 在 Cocos 预览里怎么点都正常，**只在构建产物/真机暴露**。它是「真机是验收口径」这条规矩的来源。

## BUG-003 地图上没有进关卡的入口

- **发现时间 / 发现人**：2026-09-27 / D
- **复现步骤**：预览 → 首页 → 开始游戏 → 选单人 → 地图 → 点任意关卡圆圈
- **预期结果**：进关卡
- **实际结果**：**什么都没发生**
- **根因**：`AppShellView.nodeInspector()`（唯一放着「进入当前关卡」按钮的地方）**从来没有被调用过** —— 它是更早一版「地图右边留一条节点详情栏」布局的遗留，那一版没了，函数留下了。而 `mapNode()` 的点击只调 `selectMapNode()`，那个函数只写 `selectedNodeId`，地图上没有任何地方读它。
- **严重级别**：阻塞
- **关联需求**：FR-02
- **状态 / 修复人 / 关闭时间**：已关闭 / D / 09-27（复测人：D —— 随后能进关卡并报出 BUG-005）
- **修法**：点地图节点即进关卡；`enterLevel()` 补上和 `nodeInspector` 一致的兜底选中，避免「没选中 → 静默 return」。
- **备注**：教训 —— 读别人的界面代码时，**「有这个函数」不等于「这个函数会被调到」**。只看了一眼按钮就以为入口是通的。

## BUG-005 密码门点开弹不出数字键盘

- **发现时间 / 发现人**：2026-09-27 / D（预览测试）
- **复现步骤**：进第 1 关 → 点 `hs_a_toolbox`（工具盒）
- **预期结果**：弹出数字键盘，线索栏出现「工具盒要密码（3 位）」
- **实际结果**：**键盘不出现**，看起来是「点了没反应」
- **根因**：`LevelView.openCodeGate()` 设了 `pendingCodeNodeId`，却**从来没调 `refreshInputVisibility()`** —— 而那是唯一决定键盘显隐的地方。少了这一行，键盘只能靠「下一次 `state:changed`」点亮，而这条路上永远不会再有：
  1. 运行时 `click()` 处理 use 热点时是**提前 return** 的，只报「可以输入了」，不发 `state:changed`
  2. `tick()` 只在**显示的秒数变化**时才广播 —— 而 10 关**一个倒计时、一个答错惩罚都没有**
  两条一凑 = 永远弹不出。数字键盘也只被密码门用到（两个带 puzzle 的关都是 `form` 面板，那条路走的是 `openLevelInput`，有刷）。
- **严重级别**：阻塞
- **关联需求**：FR-07
- **状态 / 修复人 / 关闭时间**：**待复测** / D / 09-27
- **修法**：`openCodeGate()` 补一次 `refreshInputVisibility()`，和 `openLevelInput()` 对齐；并加守护测试「点 use 热点只报『可以输入了』，不发 state:changed」把上面第 1 条约定钉住。

## BUG-007 顶栏「校园地图」把可玩的地图变成不可进

## BUG-008 云环境 ID 少一个字符

- **发现时间 / 发现人**：2026-09-28 / D（真机调试）
- **复现步骤**：真机/预览点「微信登录」
- **预期结果**：登录成功，同步进度
- **实际结果**：`cloud.callFunction:fail errCode: -501000 | errMsg: [100003] Env Not Exists (f960df7a-ad5d-4a88-ac5f-bf849950e333)`
- **根因**：控制台里的环境 ID 是 `cloudbase-d2gvkcg`**`h`**`abfaf9768`，代码里写成了 `cloudbase-d2gvkcgabfaf9768` —— **少一个 `h`**。环境本身没问题（控制台明写「所属应用 知行谜站 `wxf23657dd9d6612f4`」，函数也部署在里面）。
- **严重级别**：阻塞
- **关联需求**：FR-01、FR-05、FR-11
- **状态 / 修复人 / 关闭时间**：已关闭 / D / 09-28（复测人：D —— 重新构建后微信登录正常）
- **修法**：改 `ui/AppState.ts` 的 `MINI_PROGRAM_CONFIG.cloudEnv`（连带测试断言和 2 处文档）；**必须重新构建**才生效（跑的是构建产物）。
- **备注**：⚠️ **排查时被报错信息带偏了很久。** 那个 UUID `f960df7a-...` **不是我们传进去的值**（代码和构建产物里都搜不到）。真相是：**传入的环境 ID 不存在时，微信会回退到 AppID 的默认环境**，而那个默认环境也不存在了，所以报的是**它的** ID。
  **规则：见 `Env Not Exists` 就直接逐字符比对「控制台 → 概览里的环境 ID」和「`AppState.ts` 里的 `cloudEnv`」，不要跟着报错里那个 ID 走。**

## BUG-011 通关后拉 `level.list` 覆盖本地进度，刚解锁的节点消失

- **发现时间 / 发现人**：2026-10-02 / D
- **复现步骤**：云端登录状态下通关任意一关（服务端种子落后时必现）
- **预期结果**：刚解锁的节点亮着
- **实际结果**：通关瞬间亮了一下，`level.list` 回来后**当场变灰**
- **根因**：`AppShellView.persistCloudOperationCompletion()` 在 `completeLevel()` 之后又拉了一次 `level.list` 并 `applyCloudLevelList()`，把 `unlockedProgress` 整个换成服务端的。而服务端的种子落后（缺 L07~L09，且 `unlocks` 是对齐前的旧 id，认不出的会被过滤掉）→ 刚解锁的节点被过滤没了。
- **严重级别**：严重
- **关联需求**：FR-05
- **状态 / 修复人 / 关闭时间**：**待复测** / D / 10-02
- **修法**：删掉整个 `persistCloudOperationCompletion()`。这步本来就是多余的 —— `completeLevel()` 用的 `review.unlockedNodeIds` 和服务端 `unlocks` **同源**（都来自关卡配置），本地应用一次就够。服务端 → 本地的同步放在**登录时**做（`signIn` 那次），那才是对的位置。
