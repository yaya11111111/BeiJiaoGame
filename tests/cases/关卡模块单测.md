# 关卡模块单元测试用例清单

> 负责人：D。最后更新 2026-10-02。
> 代码位置：`client/tests/`（故意放在 `assets/` 外面 —— Cocos 只扫 `assets/`，放外面不会打进小游戏包体）

## 怎么跑

```bash
cd client/tests
npm install             # 新 clone 第一次
npm test                # 277 项
npm run typecheck       # 引擎无关部分（不 import 'cc' 的那部分）
npm run typecheck:view  # *View.ts，需要先用 Cocos 打开过一次工程
```

**`npm test` 通过 ≠ 类型没问题** —— vitest 只转译不检查类型。三个都要跑，缺一个就会漏掉一整类问题
（实际踩过：`EditBox` 没有 `fontSize` 属性，277 项测试全绿，`typecheck:view` 报 TS2339）。

**引擎无关**是这套测试的前提：`common/` 下的文件一律不 `import 'cc'`，所以能在 Node 里直接跑，
不用开编辑器、不用真机。`import 'cc'` 的文件必须以 `View.ts` 结尾，靠 `tsconfig.json` 的一条
`exclude` 挡在主 typecheck 外面。

## 分组明细

### `levelConfig.test.ts`（75）—— 配置写错要在加载阶段就拦住

| 分组 | 数量 |
|---|---:|
| 关卡配置校验 —— 非法配置必须被拦下 | 16 |
| 输入方式的校验 | 12 |
| use 热点（在装置上使用道具）的校验 | 8 |
| 密码门（use 热点的 code） | 6 |
| 答案形状 —— 数组是有序答案，对象是按键答案 | 5 |
| 通关条件：答题通 或 操作通，二选一但必须有一个 | 5 |
| 固定选项门（choices）的校验 | 5 |
| 配置文件路径映射 | 5 |
| 答错惩罚的配置 | 4 |
| 道具的显示名（items） | 4 |
| 关卡配置校验 —— 真实关卡能通过校验 | 3 |
| 关卡配置校验 —— 字典类字段 | 2 |

**为什么这一层这么重**：配置写错会让关卡**永远通不了**，而且只有玩到一半才发现。
所以加载阶段就拦：答案不在候选项里、道具拿不到、通关热点指向不存在的节点或不是 `submit`、
没有通关条件、道具没显示名……**报错会指明是哪一关的哪个字段**。

### `levelPlaythrough.test.ts`（45）—— 唯一的「可解性检查」

| 分组 | 数量 |
|---|---:|
| 引导关 + 第 1~9 关能通关（每关一条真实路径） | 35 |
| 解锁链条（跨关的结构检查） | 4 |
| 引导关和第 5 关的输入面板要点热点才弹出 | 2 |
| 引导关能通关 | 1 |
| （其余） | 3 |

**这一份故意和关卡设计耦合**：引擎测试用夹具是为了让设计变更不拖崩它们，但
**「这关到底能不能通」只有拿真实关卡走一遍才知道** —— 漏一个道具、一个热点忘了标
`revealsNode`、顺序串错了，配置校验全都能过，玩家却会卡死在中间。

**改动关卡设计时，这个文件里的对应路径要一起改。** 它红了不代表引擎坏了，
代表「按配置走，这一关通不了」。

### `collections.test.ts`（9）—— 构建产物守护

| 分组 | 数量 |
|---|---:|
| setToArray | 4 |
| Emitter 遍历期间被修改 | 3 |
| 源码守护：展开运算符只允许用在数组上 | 2 |

**这一份是给真机兜底的**：Cocos 的构建管线用 Babel loose 模式编译，
`[...set]` 会变成 `[].concat(set)`，而 `concat` 不展开 Set → 拿到 `[set 自己]` → 一调用就
`TypeError: s is not a function`（压缩后变量名全是 `s`，栈里根本看不出是 Set）。
**这个 bug 在 Cocos 预览里怎么点都正常，只有构建产物/真机才炸。**

所以规则是：**不要对 Set / Map 用展开运算符，用 `common/Collections.ts` 的 `setToArray()`**。
最后那一组会扫源码里每个 `[...x]`，不在白名单就失败。
