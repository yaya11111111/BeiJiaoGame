# tests — 测试记录与缺陷清单

本目录是《软件质量与测试》实训的**核心证据目录**。测试相关的一切都放这里，不要散落在各人电脑上。

## 目录约定

```
tests/
├── cases/          # 测试用例（按模块分文件）
│   ├── 关卡模块.md      # D 负责
│   ├── 外层页面.md      # E 负责
│   └── 后端服务.md      # C 负责
├── records/        # 每轮测试的运行记录（带日期）
│   └── 2026-10-05-MVP验收.md
├── bugs/           # 缺陷清单（一个文件跟踪到底，不要每轮新建）
│   └── 缺陷跟踪表.md
└── reports/        # 阶段性测试报告
```

## 缺陷记录必须包含的字段

| 字段 | 说明 |
|---|---|
| 编号 | `BUG-001` 递增 |
| 发现时间 / 发现人 | 责任人可追溯 |
| 复现步骤 | 任何人照着做都能复现 |
| 预期结果 / 实际结果 | 两者必须都写，只写"不对"不算缺陷记录 |
| 严重级别 | 阻塞 / 严重 / 一般 / 轻微 |
| 关联需求 | 对应 `docs/《断线之后》需求评审.md` 里的 FR-xx 编号 |
| 状态 | 新建 / 修复中 / 待复测 / 已关闭 |
| 修复人 / 关闭时间 | 关闭必须写复测人 |

## 与需求编号的对应关系

需求编号（FR-01 ~ FR-12）定义在 `docs/《断线之后》需求评审.md` 第 5 章。
每条测试用例、每个缺陷都应能追溯到某个 FR 编号——**这是"可追溯性"的直接证据，答辩会被问**。

## 各阶段测试分工

| 阶段 | 负责人 | 内容 |
|---|---|---|
| 单元测试 | 各模块负责人 | D 测关卡逻辑，C 测后端接口，E 测页面状态 |
| 集成测试 | C、D、E | 客户端 ↔ 后端联调 |
| 系统测试 | 全员 | 完整走通注册 → 选模式 → 关卡 → 结算 → 地图 |
| 性能 / 非功能 | C 负责服务端，E 负责客户端 | 低端手机场景加载、双人同步延迟 |
| 验收测试 | A 组织 | 每人两台不同手机完整走 3 关 |
